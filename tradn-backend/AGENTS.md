# TradN 后端开发约定

## 适用范围

- 本文件适用于 `tradn-backend/` 及其全部子目录。
- 修改代码前先阅读本文件；若子目录以后增加更具体的 `AGENTS.md`，以离目标文件最近的规则为准。
- 所有源码、配置、SQL 和文档统一使用 UTF-8，禁止改变已有文件编码或引入 BOM。

## 项目概览

- TradN 后端为黄金交易计划、开平仓复盘、Markdown 笔记、黄金时间线和系统管理提供 REST API。
- 技术基线：Java 8、Spring Boot 2.7.x、Spring Security、MyBatis-Plus、MySQL 8.0、Redis、MinIO、Quartz、Flyway、Maven。
- 服务采用无状态 JWT 认证；Redis 保存会话、限流和可丢弃缓存，MySQL 是业务事实数据的唯一来源，MinIO 保存文件对象。
- 主要业务包：`trade`（交易与问卷）、`note`（笔记）、`timeline`（每日时间线）、`file`（MinIO 文件）、`system`（系统设置与审计）、`security`（认证授权）。

## 分层与目录职责

- `controller`：定义 HTTP 路径、参数接收、Bean Validation、权限注解和统一响应；不得承载业务规则、直接操作 Mapper 或拼接 SQL。
- `service`：实现业务规则、状态流转、用户所有权校验、事务边界、缓存失效和审计记录；跨表写入必须在 Service 事务中完成。
- `mapper`：负责持久化访问。简单单表操作优先 MyBatis-Plus；统计、联表或批量 SQL 可在 Mapper 中显式定义。不得在 Controller 中使用 `JdbcTemplate`。
- `model`：数据库实体及领域数据；实体字段与表字段保持清晰映射，不在实体中放 HTTP 或页面逻辑。
- `*Command` / DTO：承载接口输入输出；新增接口禁止直接使用无约束的 `Map<String, Object>` 代替稳定 DTO。
- `common`：统一响应、异常、请求 ID 和通用基础模型，不放具体业务逻辑。
- `config`：安全、MyBatis、MinIO 等基础设施配置；配置值通过环境变量注入，不硬编码生产地址或密钥。
- `src/main/resources/db/migration`：Flyway 版本迁移；表结构、索引、基础权限和必要种子数据在此维护。
- `src/test`：单元测试和必要的集成测试，包结构应与生产代码对应。

## 命名规范

- Java 包全小写；类名使用 PascalCase，方法、变量使用 camelCase，常量使用 `UPPER_SNAKE_CASE`。
- Controller、Service、Mapper、Command 分别使用 `XxxController`、`XxxService`、`XxxMapper`、`XxxCommand` 后缀。
- REST 路径使用小写复数名词和 kebab-case，例如 `/v1/system-parameters`；动作接口只在无法表达为资源状态时使用 `/trigger`、`/force-logout` 等动词。
- 数据库表、字段、索引使用 snake_case；索引按 `uk_表_字段`、`idx_表_字段` 命名，外键按 `fk_子表_父表` 命名。
- 权限码统一为 `模块:资源:动作`，例如 `trade:record:update`；新增权限必须同步后端注解、种子数据和前端权限判断。
- 业务状态值使用大写英文常量，如 `DRAFT`、`PLANNED`、`OPEN`、`CLOSED`，禁止在不同模块创造同义状态。

## 开发原则

- 所有代码必须兼容 Java 8；禁止使用 `record`、`var`、文本块及 Java 9+ API。
- 源码必须保持便于人工阅读的多行格式：使用 4 个空格缩进，不得把多个 import、字段、注解、语句或方法压缩到同一行；较长的方法参数、链式调用和条件表达式应按语义换行。
- Controller 应添加类级说明，并为每个接口说明其用途；实体类、Command/DTO 应添加类级说明，每个属性都必须有准确的中文业务注释。
- 所有业务数据查询和写入必须基于当前登录用户校验所有权。管理员跨用户访问必须有独立权限和明确的审计记录。
- Controller 使用 `@PreAuthorize` 做接口权限校验；前端权限只改善体验，后端始终是最终安全边界。
- 多表写入、状态变更、关系替换使用 `@Transactional`；外部对象存储与数据库无法形成同一事务时，必须说明失败补偿策略。
- 更新可编辑业务数据时使用 `version` 乐观锁；冲突返回 409，禁止静默覆盖其他页面的修改。
- 金额、价格、手数使用 `BigDecimal`，禁止使用 `double`；日期边界使用半开区间 `[from, to)`，避免漏算结束日。
- SQL 必须参数化，禁止拼接用户输入；列表必须分页或设置上限，新增查询禁止无目的 `SELECT *`。
- 逻辑删除实体要同步处理唯一键占位；物理删除只用于明确允许删除的关系表、缓存或按保留策略清理的审计数据。
- 密码使用 BCrypt；密码、令牌、Cookie、密钥、完整异常请求参数和 Markdown 正文不得写入日志或审计参数。
- Redis 只存会话、限流和缓存，不存业务事实数据；缓存键必须使用已登记命名空间，清理使用 `SCAN`，禁止生产环境 `KEYS *`。
- 调度中心只允许运行代码注册的白名单任务，禁止从数据库执行任意 SQL、Shell、脚本或反射类名。
- 中文注释用于解释业务原因、状态约束、权限边界、事务/补偿策略和不直观算法；不要逐行翻译代码或保留失效注释。
- 抛出可预期业务错误使用 `BizException`；对外消息不得泄露堆栈、SQL、内部地址或密钥。

## SQL 与 Flyway 约定

- SQL 语法以 MySQL 8.0 为准，字符集统一 `utf8mb4`，默认存储引擎使用 InnoDB。
- 新表必须包含必要的主键、用户隔离字段、审计字段、逻辑删除/版本字段和支持主要查询路径的联合索引。
- 迁移文件使用 `V{序号}__{英文说明}.sql`，一个迁移围绕一个可回滚、可解释的主题。
- 每个建表或种子数据分组前添加中文注释，说明表的业务用途、关键唯一性及数据来源；复杂更新或清理 SQL 要说明影响范围。
- Flyway 迁移一旦在任一共享环境执行或进入发布基线，任何内容（包括空格和注释）都不得修改，否则会造成 checksum 不一致；后续变化只能新增迁移。
- 业务规则、状态、权限码、表结构或索引变化时，必须同步更新 `../docs/业务与数据库说明.md`。

## 新增功能实现约定

1. 先确认业务边界、用户隔离方式、权限码、状态流转和是否影响现有表。
2. 更新 `../docs/业务与数据库说明.md`；需要数据库变化时新增 Flyway 迁移，不修改已发布迁移。
3. 按 Command/DTO → Controller → Service → Mapper/Model 的顺序实现，权限、所有权、校验和事务缺一不可。
4. 涉及写操作时补充操作审计；涉及缓存时定义键格式、TTL 和失效时机；涉及 MinIO 时定义对象关系及失败补偿。
5. 新增或修改核心业务规则、状态策略、权限判断、统计口径时必须增加 JUnit 测试。
6. 完成后至少执行 `mvn test`；依赖或打包配置变化还要执行 `mvn clean package`。

## 修改限制

- 每次完成用户要求的代码修改并通过对应验证后，自动提交到本地 Git，使用准确的中文提交说明；只提交当前任务相关文件，不自动推送远程。
- 暂存文件、测试日志和联调进程状态统一放到项目根目录 `deploy/runtime/` 下，禁止生成在 `D:\work\交易`；这些产物不提交 Git。

- 禁止绕过分层、用户所有权校验、权限注解、乐观锁或统一异常处理来快速实现功能。
- 禁止修改已发布 Flyway 迁移、复用已有迁移版本号或在应用启动时临时执行 DDL。
- 禁止在源码、`application.yml`、测试或 Docker 文件中提交真实密码、令牌、私钥和生产连接信息。
- 禁止引入与 Java 8 或 Spring Boot 2.7 不兼容的依赖；新增依赖前确认必要性、许可证和维护状态。
- 禁止吞掉关键异常。允许降级的旁路能力（如审计兜底）必须有注释说明，且不得影响主业务结果。
- 禁止执行任意 SQL/脚本型调度任务，禁止未经白名单的 Redis 命名空间清理，禁止返回跨用户数据。
- 未经明确需求不得大范围重命名、迁移包、替换框架或改变公开 API；保持改动聚焦并兼容现有数据。
