# TradN 前端开发约定

## 适用范围

- 本文件适用于 `tradn-web/` 及其全部子目录。
- 修改代码前先阅读本文件；若子目录以后增加更具体的 `AGENTS.md`，以离目标文件最近的规则为准。
- 所有源码、配置和文档统一使用 UTF-8，禁止改变已有文件编码或引入 BOM。

## 项目概览

- TradN Web 是黄金交易计划、开平仓复盘、Markdown 笔记、黄金时间线和系统管理的单页应用。
- 技术基线：Vue 3、TypeScript、Composition API、`<script setup>`、Vue Router、Pinia、Vite、Ant Design Vue 4.x、Axios、md-editor-v3。
- 前后端分离，浏览器统一请求 `/api/v1`；Nginx 在部署环境将 `/api/` 反向代理到后端。
- 前端负责展示、交互和权限可见性；数据所有权、业务校验和最终权限判断必须由后端保证。

## 目录结构与职责

```text
tradn-web/
├─ src/
│  ├─ api/          # Axios 实例、拦截器和按领域拆分的 API 方法
│  ├─ layouts/      # 应用级布局、导航和用户入口
│  ├─ router/       # 路由表、懒加载和登录/权限守卫
│  ├─ stores/       # Pinia 会话及跨页面共享状态
│  ├─ views/        # 按业务模块组织的路由页面
│  ├─ components/   # 可复用业务组件（新增后放在此目录）
│  ├─ types/        # API DTO、业务状态等共享类型（新增后放在此目录）
│  ├─ App.vue       # 根组件
│  ├─ main.ts       # 应用初始化和插件注册
│  └─ styles.css    # 全局基础样式与设计变量
├─ public/          # 无需打包处理的静态资源
├─ nginx.conf       # 生产静态站点及 API 代理配置
├─ vite.config.ts   # 构建与开发服务器配置
└─ package.json     # 依赖和质量检查脚本
```

- `views` 中页面只组织当前业务场景；跨两个以上页面复用的展示或交互应提取到 `components`。
- `api` 统一处理接口调用，页面新增复杂接口时应建立领域 API 文件，避免到处硬编码路径。
- `stores` 只保存跨页面共享且确有生命周期的数据；临时表单、弹窗和加载状态保留在页面组件中。
- `types` 维护稳定 DTO 和联合类型；新增代码禁止长期依赖 `any` 掩盖接口结构。

## 命名规范

- Vue 组件文件使用 PascalCase，如 `TradeEditor.vue`；目录、普通 TypeScript 文件使用小写或 camelCase。
- 组件名、类型和接口使用 PascalCase；函数、变量、组合式函数使用 camelCase；常量使用 `UPPER_SNAKE_CASE`。
- 组合式函数以 `use` 开头；事件处理函数使用 `handleXxx`，加载函数使用 `loadXxx`，布尔值使用 `is/has/can` 前缀。
- 路由 path 使用小写复数名词和 kebab-case；路由 name 使用 PascalCase；权限码与后端保持 `模块:资源:动作` 完全一致。
- API 字段保持后端契约命名，不在不同页面创建多个同义映射；展示文案统一使用中文。

## 开发原则

- 统一使用 Vue 3、TypeScript、Composition API 和 `<script setup>`；禁止新增 Options API 或 Vue 2 写法。
- UI 使用 Ant Design Vue 4.x；表单、表格、弹窗、上传和消息提示优先复用项目已有模式。
- 页面路由、菜单和操作按钮都要检查权限；但不得把前端隐藏按钮当成安全措施，后端仍是最终权限边界。
- API 请求统一经过 `src/api/http.ts`，禁止页面自行创建 Axios 实例、重复拼接 baseURL 或绕过统一错误处理。
- 新增稳定业务对象时定义 TypeScript 类型；对后端返回值做空值和状态兜底，禁止在新代码中无理由使用 `any`。
- `.vue`、`.ts` 和样式源码必须保持便于人工阅读的多行格式，禁止提交压缩成单行的模板、脚本或样式；统一使用 2 个空格缩进，长属性、参数和表达式按语义换行。
- 表单提交期间应禁用重复操作并显示 loading；更新请求携带 `version`，遇到 409 提示刷新，禁止静默覆盖。
- 金额、价格和手数使用字符串模式传递，避免 JavaScript 浮点误差；日期提交格式必须与后端契约一致。
- 不在前端存储密码、MinIO 密钥或其他服务密钥；访问令牌只用于当前站点 API，日志和错误提示不得输出令牌。
- Markdown 预览不得信任未经清洗的 HTML；图片只能通过后端文件接口上传，不得在正文永久保存临时签名 URL。
- 时间线按日期窗口加载，缩略图使用懒加载；布局按容器宽度动态扩展为 1～5 行，并保持日期顺序。
- 中文注释用于解释权限联动、接口编排、状态转换、精度处理和不直观布局算法；不要逐行翻译模板或保留失效注释。
- 组件样式默认使用 `scoped`；全局颜色、间距和通用类放入 `styles.css`，不得用大量内联样式绕过设计规则。

## 新增功能实现约定

1. 先确认页面入口、路由、权限码、API 契约、状态流转、空态/异常态和移动端最低可用性。
2. API 类型、接口路径、权限码或业务状态变化时，同步更新 `../docs/BUSINESS_AND_DATABASE.md`。
3. 先补充 `types` 和领域 API，再实现页面/组件；复杂页面拆分为可测试、可复用的小组件。
4. 新路由使用懒加载并配置权限元信息；菜单和页面按钮使用同一个权限码来源，避免两套判断。
5. 写操作必须有提交中状态、成功反馈和失败恢复；上传要限制类型/大小并处理部分成功场景。
6. 时间线、列表和审计数据必须分页或按窗口加载；禁止一次请求全部历史数据。
7. 完成后至少执行 `npm run typecheck` 和 `npm run build`；依赖变化使用 `npm install` 更新并提交 `package-lock.json`。

## 修改限制

- 每次完成用户要求的代码修改并通过对应验证后，自动提交到本地 Git，使用准确的中文提交说明；只提交当前任务相关文件，不自动推送远程。
- 暂存文件、测试日志和联调进程状态统一放到项目根目录 `deploy/runtime/` 下，禁止生成在 `D:\work\交易`；这些产物不提交 Git。

- 禁止绕过 `src/api/http.ts`、路由守卫或权限可见性规则来快速接入接口。
- 禁止提交真实密码、令牌、私钥、生产域名和内部服务地址；禁止把敏感值写入 LocalStorage、URL 或控制台。
- 禁止直接修改 `node_modules`、`dist`、`*.tsbuildinfo`、`vite.config.js`、`vite.config.d.ts` 等生成产物；这些文件不应进入源码提交。
- 禁止未经需求引入新的 UI 框架、状态管理库、请求库或 Markdown 编辑器，避免重复技术栈。
- 禁止在新页面复制整套表格/上传/错误处理逻辑；出现重复时优先提取组件、组合式函数或 API 方法。
- 禁止使用 `v-html` 展示未经清洗的内容；禁止把 MinIO 对象设为公共读来规避签名访问。
- 未经明确需求不得大范围改版、重写路由、替换构建工具或改变接口字段；保持改动聚焦并兼容现有用户数据。
