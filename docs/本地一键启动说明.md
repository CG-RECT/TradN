# 本地一键启动说明

## 适合当前电脑的运行方式

MySQL、Redis 和 MinIO 继续使用现有 Docker 容器；后端运行打包后的 JAR，前端运行 Vite 本地服务。日常打开系统无需启动 IDEA；需要断点调试时才使用 IDEA。

项目现有 `deploy/windows/deploy.ps1` 是部署安装脚本，还需要手动配置 Nginx，不适合替代本地日常启动。全容器 Compose 适合后续服务器部署，但其默认配置会新建数据库持久化卷，不能直接当作当前已有数据库的启动快捷方式。

## 日常操作

1. 第一次切换时，手动停止 IDEA 启动的后端和终端启动的前端，避免旧服务占用端口。
2. 双击项目根目录 `start-local.cmd`。
3. 脚本检查工具、启动 Docker Desktop（如有需要），启动指定的已有依赖容器，构建并启动后端，启动前端，等待就绪后打开浏览器。
4. 用完后双击 `stop-local.cmd`，只停止由启动脚本启动的前后端。共享的 Docker 容器保持运行。

项目根目录必须有已配置好的 `.env`，用于数据库、Redis、MinIO、JWT 等连接配置。脚本不会输出这些密钥，也不会重建数据库或删除容器卷。首次后端启动仍会照常执行尚未应用的 Flyway 迁移。

默认使用当前电脑已经确认的容器名：`mysql8.0`、`redis01`、`my_minio`。其他电脑应通过 `-Containers` 指定实际容器名。

## 项目依赖总览

### 必须运行的外部中间件

| 中间件 | 当前本地容器 | 本机访问地址 | 项目用途 | 是否保存业务数据 |
| --- | --- | --- | --- | --- |
| MySQL 8.0 | `mysql8.0` | `127.0.0.1:3306` | 保存交易、笔记、时间线、用户权限、系统配置、审计日志和定时任务等数据；Flyway 也在这个库中执行结构升级 | 是，最重要 |
| Redis | `redis01` | `127.0.0.1:6379` | 保存登录会话、令牌状态、缓存和限流等短期状态 | 有短期状态，不是业务数据主库 |
| MinIO | `my_minio` | API：`http://127.0.0.1:9000`；控制台：`http://127.0.0.1:9001` | 保存笔记、黄金时间线等功能上传的图片和文件 | 是，文件对象 |

以上三个服务默认都由 `start-local.cmd` 检查并启动。它们的数据目录由现有 Docker 容器挂载保存；停止前后端不会删除容器、数据卷或数据库。

后端真正使用的连接地址以项目根目录 `.env` 为准；如果 `.env` 没有填写主机和端口，则使用 `application.yml` 的默认值：MySQL `127.0.0.1:3306`、Redis `127.0.0.1:6379`、MinIO `http://127.0.0.1:9000`。账号和密钥只保存在 `.env`，不要写进说明文档、截图或提交到 Git。

### 随后端运行、无需单独启动的组件

| 组件 | 作用 | 说明 |
| --- | --- | --- |
| Flyway | 数据库版本升级 | 后端启动时自动检查并执行 `db/migration` 中尚未执行的脚本，使用同一个 MySQL |
| Quartz | 系统调度 | 调度器运行在后端进程中，任务和状态表保存在同一个 MySQL，不需要 Quartz 容器 |
| HikariCP | 数据库连接池 | 集成在 Spring Boot 后端中，不是独立服务 |
| MyBatis-Plus | 数据访问 | 集成在后端代码中，不是独立服务 |

### 本地开发工具与非必需容器

- Docker Desktop：用于运行 MySQL、Redis 和 MinIO。若这些服务已经作为 Windows 服务安装，可使用 `-Containers @()` 跳过 Docker 操作。
- JDK 8 与 Maven：用于构建并运行后端。
- Node.js 22.12 或更高版本与 npm：用于安装依赖并运行前端。
- Nginx：本地一键启动不需要。开发环境由 Vite 提供页面并代理 `/api`；Nginx 只在服务器部署或全容器部署中使用。Docker Desktop 中停止的 `nginx01` 与当前本地启动无关。
- `minio-init`：只在全容器 Compose 部署时一次性创建私有存储桶，执行完成后退出，不是需要长期运行的中间件。
- 达梦 `dm8`：当前 TradN 没有连接它，Docker Desktop 中的该容器与本项目无关。

## 为什么 Docker 中有两个 MySQL

当前电脑上同时运行了两个彼此独立的 MySQL 容器：

| 容器 | 版本 | 容器内端口 | 映射到本机 | TradN 是否使用 |
| --- | --- | --- | --- | --- |
| `mysql8.0` | MySQL 8.0 | `3306` | `3306` | **是** |
| `mysql5.7` | MySQL 5.7 | `3306` | `3307` | 否，可能属于其他旧项目 |

判断依据不是容器名称，而是最终连接地址：当前 `.env` 没有覆盖 `MYSQL_HOST` 和 `MYSQL_PORT`，后端因此使用默认地址 `127.0.0.1:3306`；Docker 将这个端口映射给了 `mysql8.0`。一键启动脚本默认启动的也是 `mysql8.0`。

Docker 中看到的 `33060`（MySQL 8.0）以及映射为 `33059` 的端口（MySQL 5.7）是 MySQL X Protocol 端口。TradN 使用普通 JDBC/MySQL 协议连接 `3306`，不会连接这些 X Protocol 端口。

停止状态的 `mysql5.7-port3306-backup-20260811` 是旧的备份容器。它没有运行，也没有参与当前项目。不要在 `mysql8.0` 运行时启动一个同样占用本机 `3306` 的旧容器，否则会发生端口冲突。

目前无需删除或停止 `mysql5.7`，因为它使用 `3307`，不会影响 TradN；在确认其数据属于哪个项目之前也不建议删除。若以后需要确认连接目标，可执行：

```powershell
# 查看所有容器实际映射到本机的端口。
docker ps -a --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"

# TradN 当前应看到 3306/tcp -> 0.0.0.0:3306。
docker port mysql8.0

# 检查 MySQL、Redis 和 MinIO 的本机端口是否可访问。
Test-NetConnection 127.0.0.1 -Port 3306
Test-NetConnection 127.0.0.1 -Port 6379
Invoke-WebRequest http://127.0.0.1:9000/minio/health/live -UseBasicParsing
```

## 本地启动时的依赖顺序

`start-local.cmd` 按以下顺序处理：

1. 读取根目录 `.env`，但不把密钥打印到控制台。
2. 检查 Docker Desktop，必要时启动它。
3. 启动或复用 `mysql8.0`、`redis01`、`my_minio`。
4. 等待 MySQL、Redis 的 TCP 端口以及 MinIO 健康检查通过。
5. 构建并启动后端；后端连接 MySQL 后自动执行 Flyway 迁移并启动 Quartz。
6. 启动前端 Vite 服务，确认页面和代理就绪后打开浏览器。

如果中间件容器已经运行，脚本只复用它们，不会重建容器。`stop-local.cmd` 只停止本脚本启动的前端和后端，默认保留三个中间件继续运行，避免频繁启停和误伤共享数据。

## 本地模式与全容器模式不要混用

日常开发采用“复用现有中间件容器 + 本机运行前后端”的模式。`deploy/docker/compose.yml` 则是另一套完整部署方案，会创建自己专用的 MySQL、Redis、MinIO 网络和数据卷，并让后端通过服务名 `mysql`、`redis`、`minio` 连接。

两种模式的数据不是天然共享的。直接切换到全容器模式，可能看到一个全新的空数据库和空存储桶；除非明确执行过数据迁移，否则不要把它当成当前本地数据库的快捷启动方式。

## 可选参数

在项目根目录 PowerShell 执行：

```powershell
# 仅检查配置和服务状态，不启动、不停止、不构建。
.\start-local.cmd -CheckOnly

# 使用已有后端 JAR 加速启动；修改后端代码后应去掉此参数重新构建。
.\start-local.cmd -SkipBuild

# 启动但不自动打开浏览器。
.\start-local.cmd -NoBrowser

# 数据库等依赖已安装为系统服务时，跳过 Docker 操作。
& .\deploy\windows\start-local.ps1 -Containers @()

# 其他电脑配置已有容器名称。
& .\deploy\windows\start-local.ps1 -Containers @('my-mysql', 'my-redis', 'my-minio')
```

后端默认 8080（可由 `.env` 的 `APP_PORT` 或 `-BackendPort` 覆盖），前端默认 3000（可由 `-WebPort` 覆盖）。支持 `-JavaHome` 指定 JDK；未指定时优先识别有效 JAVA_HOME，再从 javac.exe 定位 JDK，避免误用 JRE。

`.cmd` 仅对本次 PowerShell 进程设置脚本执行策略，不修改电脑的全局执行策略。前端依赖存在时直接复用，不反复安装；后端默认每次新启动前构建。已经就绪的服务会被复用，不会替换 IDEA 运行的进程；后端代码更新后需手动停止旧实例，再启动新实例。

这两个 Windows PowerShell 脚本使用带 BOM 的 UTF-8，兼容 Windows PowerShell 5.1 对中文注释的读取；Java 和 Vue 源码继续使用无 BOM 的 UTF-8。

## 日志和停止范围

日志与进程记录统一在项目 `deploy/runtime/local/` 下，Git 已忽略此目录：

- `backend-build.log`：后端构建结果。
- `backend.log`、`backend-error.log`：后端运行输出。
- `frontend-install.log`：首次前端依赖安装输出。
- `frontend.log`、`frontend-error.log`：前端运行输出。
- `backend.json`、`frontend.json`：脚本所启动进程的 PID、启动时间和入口路径。

停止脚本核对进程启动时间和完整入口路径，避免 PID 被重用时误关其他程序。它不停止 IDEA 的后端、手动启动的前端及数据库容器。启动部分失败时查阅对应日志，修复后重试，或用停止脚本关闭本脚本已启动的部分服务。

可用 `-Instance verification -BackendPort 8081 -WebPort 3001 -NoBrowser` 在其他端口验证脚本。对应日志在 `deploy/runtime/verification/`；停止时执行 `deploy/windows/stop-local.ps1 -Instance verification`。不应在服务器上把 Vite 开发服务作为生产部署方案。

## 登录失效后的行为

登录依旧有有效期，不通过延长或取消有效期解决问题。令牌过期、Redis 会话清理、强制下线等情况发生后，API 返回 401，页面自动回到登录页并说明原因；重新登录后恢复原页面。尚未保存的表单内容不会自动保存。

缺少角色权限返回 403 并提示联系管理员授权，不会把仍有效的登录态清掉。旧服务重启之前仍可能使用原来的 403 返回规则，因此部署本次修复后需要重启后端并刷新前端。

后端验证命令：`mvn test`。前端验证命令：`node --test tests/session.test.mjs`、`npm.cmd run typecheck`、`npm.cmd run build`。
